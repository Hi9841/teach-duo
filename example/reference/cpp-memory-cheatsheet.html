Stack or heap

Stack

Locals, parameters, small fixed types. Automatic. Freed when the scope ends. Never leaks, never needs delete.

Heap

Anything from new or make_unique. Lives until you release it. You own the lifetime.

Rule of thumb If you wrote new, you wrote delete. If you can avoid the new by using a standard container or smart pointer, do that instead.

p and *p

int value = 5;
int* p = &value;   // p holds the address of value
*p = 10;            // writes through: value becomes 10
p  = nullptr;       // reseats: value untouched

The three failures

Leak Allocated with new, never released. Memory stays taken until the process exits.

void spawn() {
  int* hp = new int(100);
  *hp = *hp + 50;
}   // leak: no delete

void spawn() {
  int* hp = new int(100);
  *hp = *hp + 50;
  delete hp;
}   // correct: exactly one delete

Dangling Used after delete. The cell is gone but the pointer still holds the address.

int* p = new int(9);
delete p;
*p = 10;        // use after free: undefined
p = nullptr;    // now a later misuse fails loudly

Double free Two delete calls on one pointer. Undefined behaviour, and often a hard crash.

Checklist before you leave

  • Every new has exactly one matching delete or delete[].
  • No pointer is read after it was deleted.
  • Deleted pointers are set to nullptr when the lifetime continues.
  • new T[n] pairs with delete[], never plain delete.
  • Compiled with -fsanitize=address,undefined at least once.
